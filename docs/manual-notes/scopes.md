# 示波器 / 初调 / 自动调色（p3063–3160）

> 本文件是该段手册的要点摘录，重点是「模型能从画面里看到什么、不能看到什么」——
> 它直接决定了 `qing_color_grab_frame` 的提示词该怎么说。

## 1. 核心概念区分

1. **Viewer 的显示不保证按系统校准**（p3075）：调色台的监视器有校准，软件里的 Viewer 只是「参考」。所以拿 Viewer 截图去推断绝对亮度数值是不成立的。
2. **波形图必须开 Extents 才看得到过冲**（p3096）：不开的时候超出范围的信号被裁在边界上，看起来"刚好到顶"，实际上已经爆了。
3. **示波器读的是信号，不是画面**：波形 0–1023 对应 10 bit 的 0 = 绝对黑、1023 = 绝对白；它给的是分布，不是平均亮度。
4. Parade（分量）看三通道：**三条色带的高度差 = 对比/偏色线索，贴底 = 黑位，贴顶 = 白位**。
5. 矢量图看**离心方向 = 偏色**，离圆心距离 = 饱和度；肤色线（In-phase）只是**一般参考**，不是硬标准。
6. **自动/隐形调整**：`Shot Match`（p3131）与白平衡吸管（p3127）会直接改画面，但它们**不在可编辑的控件里**——想复现或撤销，只能靠节点/版本，不能靠"再调一次那个参数"。

## 2. 判读 → 参数（初调手册给的经验映射，p3146–3151）

| 看到的现象 | 该动的地方 |
| --- | --- |
| 整体欠曝 | 抬 Gamma / Shadows |
| 高光溢回收不回来 | 收 Gain / Highlights |
| 肤色偏绿 | Tint 往品红方向 |
| 对比不足 | 加 Contrast，配合 Pivot |
| 暗部偏色 | Lift |
| 高光偏色 | Gain |
| 整体偏色 | Offset |

## 3. 破坏性 / 不可逆

1. 本节讲的都是**基础调色控件**的调节，本身可撤销（Resolve 原生 Undo）；但 `Shot Match` 与白平衡吸管一旦应用，撤销要依赖 Undo 栈或版本回滚。
2. 示波器本身只读，不改画面。

## 4. API 可覆盖但当前工具未覆盖

1. 没有任何脚本 API 能读到示波器数值——`Project`/`Graph` 里没有波形/矢量图的取值接口。**只能截图 + 自己算像素统计**，这正是 `qing_color_grab_frame` 里 `_frame_stats()` 的定位。
2. **版本（Version）** 是初调最安全的做法：调坏了切回旧版本。API 侧有 Gallery / still 相关接口，但没有"切版本"的直接方法——要靠在画廊里管理 still。

## 5. 现有工具描述的错误 / 不准确

1. `qing_color_grab_frame` 早期版本会让模型"根据截图判断曝光/溢出"——**这是错的**：截图是 8 bit 显示参考，不是 IRE，也不是 1023 刻度。正确说法是「看构图、看肤色、看整体倾向」，精确信号判断要用户自己看示波器。
2. 因此该工具现在会额外返回像素统计（死白/死黑面积比、亮度分位数、平均饱和度）并附 `measurement_caveat`，同时明确「不要宣称溢出了百分之几」。

## 6. 一句话结论

**截图不能当示波器**：能把构图、肤色、整体倾向说清楚就够了；任何"这个高光溢出了 X%"的说法都是编的。
